# Architecture

Scenario models unit-specific Workshop upgrades and side Forge; registry models domain, role/support effect, semantic class, native line, size, and per-weapon accuracy/ammo. Packaged mechanics, units, Workshop, Forge, support, formation, targeting, battle-end, and calibration data load through `importlib.resources`. An immutable registry provides all five executable land geometries as the single authority for slot space and deployment order; community slot geometry and empirical damage-position evidence retain distinct provenance. Battlefield choice is explicit scenario input; Town Hall ranges are metadata, with no automatic selection, garrison/wall escalation, or mid-battle resizing. The pure planner validates and executes profile eligibility, fallback eligibility, and Heavy-before-Light/front-before-flank precedence, assigning runtime `Slot.line` without mutating native metadata. The formation layer also exposes eligible runtime lines so safety checks consume the same native/fallback contract rather than duplicating it. Art of Warfare target priority is a known runtime-line role contract. The independent weapon-selection layer preserves primary weapons for native combat and selects the sole registry weapon for runtime-first Light Infantry; damage calculation consumes that selected weapon and reports its ID/trigger. Multi-weapon fallback remains unsupported. Mixed runtime lines are representable but mixed-unit Am remains guarded. Multi-line `Wave` execution remains guarded as `UNKNOWN-MULTILINE-WAVE-COMBAT-SEMANTICS`; wholly reserve-only waves eligible for an occupied runtime line are guarded as `UNKNOWN-CROSS-WAVE-FORMATION-REBUILD`. Round-start same-wave formation rebuild precedes RR.

Battle-report calibration is an executable layer beside, not inside, combat mechanics. `run_fixture()` invokes the engine and delegates to `evaluate_fixture()`, which consumes JSON-shaped snapshots/events. It addresses slots by side/runtime line/damage position, resolves unit HP through the fixture profile, and uses additive damage-event target identity for exact-slot casualty aggregation. Independent field assessments preserve explicit unknowns; a calibration match never promotes evidence into a production rule.


The browser is now treated as a battle workbench with three presentation states: setup, round replay, and total report. Setup consumes canonical unit/battlefield metadata and converts only non-zero rows into the existing Scenario contract; combat rules remain exclusively in the engine. Round rendering mirrors the two sides around the contact line with attacker above and defender below, keeps reserves separate, and derives every visible line/slot from battlefield metadata. The engine's round-0 deployment snapshot is preserved for inspection but labeled `部署` in the pager so it is not confused with an in-game battle round. Total reporting now adds an evidence-backed land military-economy layer without changing combat math. The economy profile stores each player's unmodified resource score basis and validates `General Score = basis / 50`; the public simulator wrapper derives score lost/destroyed from casualties after core combat returns. Gross damage reporting is separately derived by summing emitted damage events and is explicitly not conflated with military score.
