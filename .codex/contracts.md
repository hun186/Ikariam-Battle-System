# Interface Contracts

`simulate` input contains profiles (`mechanics`, `unit_stats`, `workshop`, `forge`, `support`, `targeting`, `battle_end`, `formation`), policy, `land-mini`, max rounds, and armies with side `forge_level` plus `units[{unit_id,quantity,wave_id,attack_upgrade,armor_upgrade}]`. Upgrades are non-negative integers; same unit on one side must use consistent upgrades. Strict unsupported behavior is inconclusive; experimental assumptions have stable, unique IDs and only report applied policies. Snapshots keep `total` and add `main_line_holding_total`, `fallback_candidate_total`, and `continuation_state`; termination is a separate event and never fabricates casualties. `fallback_required` is an inconclusive boundary in both policies.

`GET /api/simulate` returns the canonical `Profiles()` bundle (including `formation`), verified-through metadata, supported/reserved battlefields, complete units with domain/role/support effect plus semantic class/native line, Forge levels and support capacity. `POST` returns result or 400 validation error. Packaged data is the registry authority; UI has no duplicate list. `attacking_matrix` additively exposes `weapon_id`; `damage_calculation` exposes `weapon_id` and `weapon_trigger` from the explicitly selected weapon.

Wave identity is entry-batch identity. Ammo live pool and frozen normal entry capacity belong to the wave and are shared by all of its slots; the percentage is Phase-A-derived rather than a verified game tooltip formula. Snapshot `waves` and additive slot fields expose entry batch, display/taxonomy, upgrades, engine-derived slot-level surviving-unit HP percentage, and wave-level munition percentage. `Wave.slots` can structurally represent more than one runtime line, but `UNKNOWN-MULTILINE-WAVE-COMBAT-SEMANTICS` prevents that uncalibrated state from entering rebuild, RR, targeting, or fire. A wholly reserve-only combat wave that formation rules make eligible for an occupied runtime line is guarded by `UNKNOWN-CROSS-WAVE-FORMATION-REBUILD`; eligibility includes native and fallback placement, while ordinary reserve refill within one wave remains supported. Heavy/Light runtime-first formation is representable. A homogeneous, single-weapon Light runtime-first wave is executable: weapon selection uses its sole weapon while targeting uses runtime first-line priority. `UNKNOWN-FALLBACK-LIGHT-INFANTRY-COMBAT` is limited to non-native Light without a uniquely selectable weapon; `UNKNOWN-MIXED-UNIT-AM-ROWS` still blocks mixed source rows. Native ranged combat selects primary and retains the existing wave ammo/partial-volley/exhaustion behavior; ranged fallback and secondary triggers remain unsupported.

`BattleReportFixture` remains backward compatible and optionally carries `fixture_id`, `evidence_class`, and `source_note`. `evaluate_fixture(fixture, simulation_result)` and `run_fixture(fixture)` return `CalibrationResult`; `as_dict()` is JSON-serializable and includes simulation status, reached round, blockers, and ordered per-field assessments. Assessments are `match`, `mismatch`, or first-class `not_assessable`. Damage percent compares persistent integer damage with the documented round-up interval over surviving slot HP. Casualties use only same-round `damage` events addressed by `target_side`, `target_line`, and `target_damage_position`; those event fields are additive observability. Battle-report life percent is retained but returns `UNKNOWN-BATTLE-REPORT-LIFE-PERCENT-SEMANTICS`. Missing/ambiguous rounds or slots never fall back to another identity.
