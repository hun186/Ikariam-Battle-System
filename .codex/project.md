# Project Profile

Initialized evidence-aware Phase A Ikariam browser simulator. Python 3.11+, pure `ikariam_battle.simulate()`, no-framework ASGI/Vercel, vanilla UI, packaged profiles under `ikariam_battle/data/`.

Inputs are profile bundle, explicit battlefield ID, strict/experimental policy, side-wide Forge, unit-specific Workshop levels, units/waves. Outputs include positioned slots, reserve, ammo-pool shots, damage/casualties, all-survivor totals, main-line/fallback continuation state, termination events, and assumptions actually applied. Function B is excluded.

Facts: reviewer-web-verified current data through 17.5.0 is distinct from empirical PDF mechanics. All five land geometries are operational through explicit manual IDs; naval geometry and automatic Town Hall/garrison selection or transitions remain unsupported. Player defender Town Hall 1..66 and Town Wall 0..46 are explicit scenario/UI inputs. Player garrison-limit/open-field start is executable using actual unit counts with v17.4 Doctor/Cook exclusion; threshold crossings are detected but cross-geometry transition execution is guarded. Published wall stats/segments are represented, while active wall targeting/breach/refill/flank-lock semantics remain guarded. Barbarian garrison auto-calculation is unresolved because community formulas conflict. Duplicate same unit/wave/upgrades normalize; contradictory same-unit upgrades reject; input ordering is not a rule; ammo is pooled shots; support healing and morale are distinct; unknowns never silently produce exact strict outcomes.
