Ikariam Battle Simulator

以遊戲戰場操作直覺呈現的 evidence-aware 戰鬥模擬器。未知機制仍會安全停止，不假造結果。

預設 100 回合；1000 回合是可手動提高的安全上限，不是固定戰鬥長度。長戰的逐回合資料會按需分頁載入，不會一次傳送全部回合。若提早分出勝負或遇到無法安全判定的機制，模擬會提早停止。Cook 士氣目前尚未完整建模；實戰常見約 15 Cook 的配置不會被當成已驗證的固定公式。
快速設定 / Presets需要時展開；預設收合。內建快速設定、自訂套裝與兵力歸零都在這裡；自訂套裝只保存在此瀏覽器。
自訂套裝使用瀏覽器 localStorage；不會上傳到伺服器，也不會改變模擬規則。
Debug JSON 可直接貼回來協助重現問題；不包含 API key。

攻擊方

防守方

預設仍維持最大陸戰戰場與 Player Lv5 熔爐、單純前線，避免一打開就塞滿大量兵力；需要多戰線驗證時可用上方「綜合陸戰」快速設定。Player 防守方可設定市政廳 Lv1–66 與城牆 Lv0–48；駐軍上限 = 250 + 50 × (市政廳 Lv + 城牆 Lv)。Barbarian 防守方可設定村落 Lv1–50；目前 2024 Gameforge 論壇實戰規則為 (村落 Lv + 城牆 Lv + 5) × 50。兩者依 v17.4 排除 Doctor / Cook（海軍則排除 Tender）；守軍數高於上限時先以最大陸戰戰場進行野戰、城牆不出場。當傷亡使守軍回到上限內時，模擬會偵測到應縮回原戰場／城牆重現的 transition；同為 land-max 的 state-only 回復可讓新鮮城牆於下一回合重新出場，跨 geometry 重建仍停在 UNKNOWN-GARRISON-BATTLEFIELD-TRANSITION。Strict 的 active-wall 戰鬥停在 UNKNOWN-TOWN-WALL-COMBAT；Experimental 可執行具名假設下的 Artillery 破牆、破口 First 暴露、Flank lock 與可整除牆傷重分配。每列的 ±一格 由目前戰場的 slot space ÷ unit size 動態計算。Barbarian 套裝固定無 Workshop、無 Forge、無分批進場，軍分為 0；目前兵力數量仍由使用者手動輸入，不會依村落等級自動產生。
野蠻人兵種資料與出現等級（9 種）
Barbarian Village 陸軍兵種已可作為獨立 Army package 進入模擬；這裡保留來源、數值與首次出現等級參考。若設定 Village Lv，駐軍上限採 2024 Gameforge 論壇的現行社群實戰規則：(Village Lv + Wall Lv + 5) × 50；這不是 Gameforge 官方規格。較舊 guide 的 ≈250 + 75 × Wall 僅保留為歷史近似。完整守軍數量與城牆等級仍不會由 Village Lv 自動生成。

戰鬥機制狀態 / Mechanics Status

這一頁是模擬器正確度的核心依據：已知且可執行的規則會明確標示；部分已知或仍未知的機制則代表目前模擬器的限制。遇到無法安全判定的規則時，Strict 模式會停止，而 Experimental 模式只會在有明確 named assumption 時繼續。

開火順序 / Firing order · 已知

Air defence → Air → Artillery → Flanks → Long-range → Main battle line。同一 formation 的攻守雙方同時取得射擊資格；較早 formation 造成的死亡會讓該兵在較晚 formation 無法再開火。

目標優先序 / Target priority · 已知

每個 formation 依自己的 priority list 選目標；但會先做 weapon-specific 穿甲判定：effective ATK 必須嚴格大於 target effective DEF，ATK ≤ DEF 的候選直接跳過、不開火也不耗彈，再找下一個可傷害目標。一般無牆時 Artillery 為 Main → Flank；有 active Town Wall 時已知為 Wall 優先於普通 First。Flank 為 Flank → Long-range → Artillery → Main。

Accuracy / Precision · Experimental concentration-v1

官方演算法仍未知，Strict 仍以 UNKNOWN-ACCURACY 停止。Experimental 不把 Accuracy 當每發獨立命中率：能一擊殺死滿血目標的攻擊不製造 miss；非 one-shot 時，若最殘血目標的剩餘 HP% 仍高於武器 Accuracy，就先把傷害分散給較健康目標；降到 Accuracy 以下後才集中攻擊最殘血目標。這只影響已選定 slot 內的 individual target，不改變 Attacking Matrix、formation priority、Damage、Ammo 或開火順序。

RR · Reserve Redistribution · 已實作

回合間，同一 entry batch / wave 的 persistent damage 會連同 reserve 一起重新分配；不同 wave 不共享舊傷。

IR / SR · Trigger 未知，現在不觸發

IR 可能發生在 individual shots 之間；SR 可能發生在一條 formation 射完、下一條 formation 開火前。引擎保留 redistribution hook，但 trigger 尚未確立，因此目前固定不觸發。

D-kill / P-kill / I-kill · 部分已知

目前 Experimental baseline 使用逐擊 D-kill：一發一發計算，死亡立即生效，overkill 預設丟棄。P-kill 在部分實戰會把 overkill 重新分配給 survivors；I-kill、IR-kill、PIR-kill、M-kill 亦有實驗觀察，但一般觸發條件仍未知，因此目前不自動套用。

Healing / Repair · 部分已知 / 部分實作

Doctor 只治療 Human，Machine 不可治療；現行容量為每名 Doctor 4000/回合。Tender 從 Reserve 發揮效果，現行修護容量同樣為每艘 4000/回合，適用海軍 combat units。當 Doctor 或 Tender 的總容量足以清除全部符合資格的 persistent damage 時，引擎會直接 full-clear；這個結果不受 Healing / RR 先後影響。容量不足時，allocation 與精確 Healing / RR 順序仍未知，因此不猜部分分配。

RR 後 slot 內部傷害分配 · 未完全確立

PDF 能確立 wave → slot 的 RR，但 slot aggregate damage 如何落到 individual units 仍有未解處。Experimental 現採均勻分配後再逐擊，並以 named assumption 顯示。

Garrison / Open field · 部分實作

Player 陸軍駐軍上限 = 250 + 50 × (Town Hall Lv + Wall Lv)；Barbarian 若設定 Village Lv，採 2024 Gameforge 論壇社群規則 (Village Lv + Wall Lv + 5) × 50。判斷使用實際兵隻數，不看 unit Size；v17.4 起 Doctor / Cook 不計。守軍嚴格大於上限時使用 land-max 野戰且城牆不出場；等於上限仍非野戰。戰鬥中跨回上限時會偵測到 transition，但跨 geometry 的 wave / damage / ammo 重建尚未校準，因此以 UNKNOWN-GARRISON-BATTLEFIELD-TRANSITION 停止。

Town Wall / 城牆 · Infinite Horizons 數值已更新

防守方可設定 Lv0–48。每段城牆 HP = 1800 + 900 × Lv、Armor = 72 × Lv；Damage 則沿用舊三段公式再 ×18：Lv1–9 = (10 + 2×Lv)×18、Lv10–19 = (30 + 5×Lv)×18、Lv20+ = (50 + 10×Lv)×18。現行觀察點 Lv1=216、Lv9=504、Lv18=2160、Lv26=5580 均吻合。已知 active Wall 存在時攻方 Land Artillery 優先 Wall，且打不穿 Armor 的 weapon 不把 shot 浪費在牆上。Strict 仍停在 UNKNOWN-TOWN-WALL-COMBAT；Experimental 已執行牆段 HP／破洞、破口對應 First 暴露、任一牆段存活時 Flank lock、以及可整除的回合間牆傷重分配。牆段先後順序與每個可穿甲 Artillery ticket 視為 successful wall hit 都是具名 Experimental assumption；Wall 本身 Accuracy／個體目標、非整除重分配與跨 geometry transition 仍未校準。

海戰 / Naval · naval-max 已可執行

官方 Help 已明確給出各 formation 的填格強弱順位、目標優先序、填格總順序與開火順序；因此這些已不再是陸戰類比假設。現行順序為 Carrier Evasion → Carrier → First Strike → Flank → Long-range → Front，同 formation 雙方同時射擊。AM、RR、Damage、Ammo 共用同一引擎。Long-range 無彈藥後補 Front 已沿用陸戰同型的 whole-wave round-start fallback：primary ammo 歸零後，若 Front 空位足以容納整個 surviving wave，就移入 Front、保留 persistent damage 並在 RR 後使用 secondary/hull weapon。若同一 wave 必須同時跨 Long-range / Front，仍由共用 multi-line guard 停住。仍待校準的是一般 D/P/M/IR/SR selector，以及 Tender 容量不足時的修護 allocation。Tender 現行修護量為每艘每回合 4000；容量足以全清 naval persistent damage 時已可安全套用 full-clear。

如何解讀這一頁：「已知」不代表所有細節都來自 Gameforge 原始程式碼，而是代表目前有足夠 evidence 支撐可執行 contract；「部分已知／未知」就是結果精度的邊界，不應被模擬器悄悄猜成確定答案。

研究來源：Ikariam Battle System PDF

本專案的重要理論基礎之一，是 2020 年玩家社群整理的 Ikariam Battle System。它把多年戰報、測試與推理整理成可分析的 Attacking Matrix、damage-position 與 Redistribution 等模型，為今天這個模擬器提供了非常重要的研究起點。
